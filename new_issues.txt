ISSUE #7: Memory Leak — Event Listeners Not Cleaned Up on Unmount
================================================================================
File: src/risc_v_visualizer.jsx, EncodingDiagram component (lines 403-426)

Description:
The `EncodingDiagram` component adds a `resize` listener on `window` and a
`scroll` listener on the scroll container. While the cleanup function removes
both, there is a race condition: `requestAnimationFrame` callbacks may fire
after the component unmounts because `cancelAnimationFrame` is called in the
cleanup but the `rafRef` could have been set to null prematurely if the
cleanup runs between the RAF scheduling and firing.

Additionally, the `window.setTimeout` calls for copy status feedback
(lines 3118, 3487) are never cleaned up. If the component unmounts before
the timeout fires, it will attempt to call `setCopyStatus` or
`setEncoderValidatorCopyStatus` on an unmounted component.

Impact: MEDIUM — Potential "setState on unmounted component" warnings and
minor memory leaks in React strict mode / fast navigation scenarios.

Fix (estimated 35-40 lines):
- Store timeout IDs in refs and clear them on unmount
- Add a mounted ref flag to guard setTimeout callbacks:
  ```
  const mountedRef = useRef(true);
  useEffect(() => { return () => { mountedRef.current = false; }; }, []);
  ```
- Guard all setTimeout setState calls: `if (mountedRef.current) set...()`
- Ensure RAF cleanup is race-free by checking rafRef.current in cleanup

ISSUE #9: Sync Script Uses `vm.runInNewContext` — Security Risk & Fragility
================================================================================
File: scripts/sync_instructions.mjs (line 80)

Description:
The sync script extracts `extensionInstructions` from the JSX file by:
  1. Finding the string `const extensionInstructions =`
  2. Extracting the text between matching braces
  3. Running it through `vm.runInNewContext()`

This approach:
  - Executes arbitrary JavaScript from the JSX file in a sandboxed VM context.
    While sandboxed, this is fragile and could execute unexpected code if the
    JSX format changes (e.g., if the object uses imports, function calls, or
    template literals).
  - Relies on regex-like brace matching that doesn't handle all JS edge cases
    (e.g., regex literals containing braces, multi-line template literals
    with nested expressions).
  - The escape detection on line 25 uses `\\\\` which looks like a double
    backslash literal, not a single backslash character check.

Impact: MEDIUM — Fragile extraction that will break if the data format
evolves. Potential security concern if untrusted JSX is processed.

Fix (estimated 50-60 lines):
- Move `extensionInstructions` to a separate JSON or JS data file
  (`src/data/extension_instructions.json`) that can be imported by both
  the visualizer and the sync script without vm.runInNewContext
- The sync script would simply `JSON.parse(fs.readFileSync(...))` the
  instruction mapping
- Update the visualizer to `import extensionInstructions from './data/...'`
- Remove the brace-matching and vm.runInNewContext code
- Add proper error handling with descriptive messages

ISSUE #15: Search Side Effects in useEffect — Should Use Debouncing
================================================================================
File: src/risc_v_visualizer.jsx (lines 2450-2518)

Description:
The search useEffect runs on every keystroke (fires whenever `searchQuery`
changes). For each keystroke it:
  1. Iterates all extensions to find matches
  2. Iterates all instructions within matched extensions
  3. Updates selectedExt, searchMatches, and selectedInstruction state
  4. Triggers DOM scrollIntoView

With ~222 extensions and potentially thousands of instructions, this runs
O(n*m) matching on every keystroke with no debouncing. The state updates
cause re-renders of the entire component tree on each keystroke.

Impact: MEDIUM — Perceived input lag on slower devices, excessive re-renders,
janky scroll behavior during fast typing.

Fix (estimated 40-45 lines):
- Add a debounce mechanism (300ms) before running the search:
  ```
  const [debouncedQuery, setDebouncedQuery] = useState('');
  useEffect(() => {
    const timer = setTimeout(() => setDebouncedQuery(searchQuery), 300);
    return () => clearTimeout(timer);
  }, [searchQuery]);
  ```
- Move the search effect to use debouncedQuery instead of searchQuery
- Use useMemo or precomputed index for faster lookups
- Consider using a Web Worker for search in large datasets
- Show a "searching..." indicator during the debounce period

ISSUE #17: Copy-to-Clipboard Fallback Uses Deprecated `document.execCommand`
================================================================================
File: src/risc_v_visualizer.jsx (lines 2101-2129)

Description:
The `copyTextToClipboard` function first tries `navigator.clipboard.writeText`,

fallback is only needed for very old browsers, but when it runs, it uses
deprecated APIs.

Fix (estimated 30-35 lines):
- Remove the execCommand fallback entirely (clipboard API is supported in
  all browsers since 2020)
- OR replace with the Clipboard API's fallback using ClipboardItem
- Add proper error messaging when clipboard access is denied (e.g., in
  insecure contexts / non-HTTPS)
- Show a "Copy failed — clipboard access denied" toast with instructions
  to use Ctrl+C manually
- Add a fallback that shows the text in a selectable textarea modal
  (instead of trying to auto-copy)
